**Приложение Windows для семейного учёта времени: архитектура и проектный промпт**

Версия 0.2 · 28 сентября 2026 года · Черновик для обсуждения.

Зафиксированные пожелания владельца: приложение для Windows с установщиком EXE; учёт времени в играх, приложениях и YouTube; автоматические отчёты родителю в Telegram; запрос текущего отчёта родителем через Telegram в течение дня; настраиваемый родителем дневной лимит общего компьютерного времени с уведомлением родителю и уведомлением на компьютере ребёнка; публичное распространение через GitHub; добровольные донаты. Сейчас требуется проектирование, без написания кода.

Изменения версии 0.2: запросы отчётов и дневные лимиты с уведомлениями включены в первую версию продукта. Автоматические блокировки остаются за её пределами. Предупреждение за 10 минут до окончания — дополнительное предложение, которое можно отключить; 2 часа — пример лимита, а не неизменяемое значение.

Остальные решения ниже — предлагаемые исходные настройки, а не уже одобренные владельцем требования. Название продукта, оформление, платёжный сервис, лицензия и окончательная совместимость ещё не выбраны. Для сборки окончательного задания этот документ можно уточнять целиком.

**Начало промпта для следующего этапа работы**

Ты — архитектор и разработчик настольных Windows-приложений. Помоги создать публично распространяемое приложение для семейного учёта компьютерного времени. Общайся с владельцем по-русски, объясняй продуктовые решения простыми словами.

Текущий режим — проектирование. Пока пользователь отдельно не поручил начать разработку, не создавай исходники приложения, сборочные конфигурации или репозиторий и ничего не публикуй. Обсуждай архитектуру, возможности, ограничения и уточняй эту спецификацию. После поручения начать разработку используй её как основу реализации. Не выдавай предложенные настройки за согласованные.

**1. Польза для пользователя**

Родитель устанавливает приложение на компьютер ребёнка и получает понятный ответ: когда компьютер использовался, сколько времени пришлось на каждую игру, программу и сайт, какие были перерывы и насколько полны измерения. Отчёты приходят в выбранный родителем Telegram-чат автоматически и по запросу. Родитель задаёт дневной лимит и получает сообщение при его достижении; ребёнок получает уведомление на компьютере и видит оставшееся время.

Приложение измеряет наблюдаемую активность программ. Оно не устанавливает, смотрел ли ребёнок на экран, чему научился, насколько полезно провёл время или что именно писал в программе. Название сайта не доказывает цель его использования: YouTube может содержать и уроки, и развлечения.

Модель распространения — бесплатный основной функционал и добровольная поддержка разработки. Учёт должен работать без учётной записи на сервере разработчика и без обязательной оплаты.

| Область | Исходное предложение |

| Учётные записи | Один компьютер и одна выбранная учётная запись Windows ребёнка |
| Браузеры | Chrome и Edge, обычный режим; первоначально по одному настроенному профилю в каждом |
| Язык интерфейса | Русский; строки вынести в ресурсы для последующего перевода |
| Хранение | Локально на компьютере; передавать в Telegram только выбранную сводку |
| Telegram | Собственный бот семьи, один настроенный личный чат родителя; автоматические отчёты и запросы текущей сводки |
| Дневной лимит | Настраиваемое общее активное время за день, например 120 минут; уведомления родителю и ребёнку |
| Донаты | Открытие страницы поддержки во внешнем браузере |
| Жёсткие блокировки | В первую версию не входят; после уведомления учёт продолжает фиксировать превышение |

Обычная установка выполняется для наблюдаемой учётной записи Windows. Если установщик запущен из другой учётной записи, это нужно ясно объяснить: учёт родителя нельзя молча принять за учёт ребёнка. Работа с несколькими детьми, несколькими ПК и несколькими одновременно открытыми профилями браузера — отдельное расширение архитектуры.

**3. Техническая основа**

Предложение на дату документа: C# и .NET 10 LTS, WPF для интерфейса, SQLite для локальной истории, расширение Manifest V3 для Chromium-браузеров. Перед разработкой перепроверить поддерживаемые версии платформы и зависимостей. .NET 10 поддерживается до ноября 2028 года [1]; WPF предназначен для Windows [2].

Модуль расчёта времени должен быть отделён от Windows API, базы и интерфейса. Подменяемые источники времени и событий позволят проверять реальные сценарии без запуска игры или ожидания полуночи. Не привязывать основную логику к UI-таймеру.

Для пользователя результат — один понятный установщик EXE. Внутри установленного приложения допустимы отдельный исполняемый файл для связи с браузером и необходимые зависимости. Сборка должна включать нужный .NET runtime; установка SDK пользователю не требуется. Не обещать один физический EXE для всех внутренних компонентов.

**4. Компоненты и границы ответственности**

| Компонент | Назначение |
|---|---|
| Приложение в сеансе ребёнка | Автозапуск после входа Windows, видимый значок в области уведомлений, сбор событий, расчёт времени, хранение и отправка отчётов |
| Окно приложения | Сегодня, история, категории, состояние подключения, настройки и поддержка проекта |
| Адаптер Windows | Активное окно и процесс, время последнего ввода, блокировка, смена сеанса и сон |
| Расширение браузера | Активная вкладка, домен, состояние фокуса окна и воспроизведение YouTube |
| Native Messaging Host | Ограниченный локальный мост между расширением и запущенным приложением |
| Движок учёта | Единственный источник правил длительности, категорий и полноты данных |
| SQLite | Интервалы, агрегаты, настройки, дневные лимиты, состояния порогов, принятые команды и очередь сообщений |
| Клиент Telegram | Получение авторизованных запросов, доставка отчётов и уведомлений, повторные попытки и диагностируемые ошибки |
| Модуль дневного лимита | Расчёт потраченного времени, остатка и превышения; создание событий при пересечении порогов |
| Уведомления Windows | Локальные предупреждения ребёнку, счётчик в интерфейсе и диагностика возможности показа |

Приложение запускается самостоятельно при входе пользователя и продолжает учитывать игры при закрытом браузере. Закрытие окна настроек сворачивает приложение в область уведомлений. Отдельные явные действия позволяют приостановить учёт или выйти; эти состояния отображаются.

Для первой версии не нужен привилегированный Windows-сервис. Наблюдение за рабочим столом выполняется в интерактивном сеансе пользователя: Windows-сервис в Session 0 не является заменой такому агенту [3].

Расширение связывается с Native Messaging Host, а он — с приложением через локальный именованный канал, ограниченный текущим пользователем. Разрешать только известные идентификаторы нашего расширения, проверять схему, размеры и происхождение сообщений. Браузер официально поддерживает Native Messaging [4]. Не открывать сетевой порт для приёма произвольных сообщений с сайтов. Предусмотреть восстановление соединения после перезапуска компонентов и совместимость версий протокола.

Не строить учёт на предположении, что таймер расширения всегда работает: жизненный цикл Manifest V3 допускает остановку service worker. Соединение Native Messaging помогает поддерживать его работу, но разрывы всё равно необходимо обрабатывать [5].

**5. Правила измерения времени**

Ключевой принцип: одна секунда входит в основной итог максимум один раз. Длительности хранить с достаточной точностью, суммировать до округления, округлять только отображение.

Основная шкала состоит из непересекающихся интервалов: наблюдаемая активность, предполагаемый простой, блокировка/сон/неактивный сеанс, пауза учёта и отсутствие наблюдений. Последнее не означает, что ребёнок пользовался компьютером: приложение могло быть выключено вместе с ПК.

Активность связывать с программой на переднем плане. Запущенная, но свёрнутая игра не продолжает накапливать основное игровое время. Веб-сайты являются детализацией времени браузера: нельзя прибавлять время YouTube к уже учтённому времени Chrome и выдавать сумму за общий итог. В разрезе программ показать браузер целиком, в разрезе занятий заменить его известные интервалы конкретными сайтами. Эти разрезы — разные представления одних интервалов.

Windows предоставляет активное окно и сведения о последнем вводе в текущем сеансе [6, 7]. Предлагаемый порог предполагаемого простоя — 5 минут без наблюдаемого ввода. В базовом режиме простой начинается после истечения этого порога; первые 5 минут остаются в оценке активности. Это приближение, которое нужно объяснить в интерфейсе и сделать настраиваемым.

Воспроизведение видео обрабатывается отдельно. Если браузер на переднем плане, нужная вкладка выбрана и видео воспроизводится, отсутствие движений мыши само по себе не переводит этот интервал в простой. Учитывать паузу, завершение, ожидание загрузки, переход между роликами и движение позиции воспроизведения. Считать прошедшее реальное время, а не длительность видео: 10 минут просмотра со скоростью 2× дают 10 минут учтённого времени. Переход по шкале ролика не добавляет часы. Состояние медиаплеера доступно через стандартные браузерные интерфейсы [8, 9].

YouTube в неактивной вкладке или за игрой учитывать как отдельный дополнительный показатель «Фоновое воспроизведение», не прибавляя его к основному итогу. На первом этапе не гарантировать определение внимания при нескольких мониторах и режиме «картинка в картинке»; не называть воспроизведение доказанным просмотром.

Пример приёмки: 20 минут Minecraft при одновременно проигрывающемся фоновом YouTube должны дать 20 минут основного времени и отдельные 20 минут фонового воспроизведения. Не 40 минут общего использования.

Игры с контроллером требуют отдельной проверки. GetLastInputInfo нельзя считать достаточным доказательством отсутствия игровой активности. Предусмотреть источник активности XInput-совместимых контроллеров; пока он не реализован и не проверен, явно ограничить поддержку и не обещать точного определения простоя для всех геймпадов. Постоянное ненулевое положение стика не должно бесконечно продлевать активность из-за дрейфа.

Блокировка, сон, выход или переключение с наблюдаемой учётной записи останавливают начисление основного времени. Разблокировка не добавляет промежуток сна в последнюю игру. Отслеживание уведомлений сеанса поддерживается Windows [10].

Для длительности использовать монотонное время, для календарных отчётов — UTC и явно выбранный часовой пояс. Обрабатывать перевод часов и смену даты. Не считать большой разрыв между наблюдениями непрерывной активностью последней программы.

Обновлять данные по событиям и выполнять контрольный опрос примерно раз в 1–2 секунды. Сохранять интервалы при изменении состояния и делать контрольное сохранение примерно раз в 5 секунд. Эти значения являются проектными настройками и подлежат проверке по нагрузке и точности. После аварии не придумывать неизвестный хвост интервала.

**6. Сайты, категории и качество данных**

Первоначальные категории: игры, видео, общение, учёба, творчество, другое. Применять локальные правила по приложению и домену. Давать родителю возможность поменять категорию и сохранить правило. Не выдавать автоматически предложенную категорию «учёба» за доказанный учебный процесс.

По умолчанию хранить название приложения и нормализованный домен сайта. Полные URL, поисковые запросы, содержимое документов, переписку и введённый текст для задачи подсчёта времени не собирать. Названия YouTube-роликов и каналов — возможная отдельная функция следующей версии, включаемая осознанно.

Расширение может получать свойства текущей вкладки с разрешением tabs; состояние воспроизведения требует отдельного доступа к поддерживаемому сайту [11]. Ограничить внедрение скриптов нужными доменами. В обычном режиме инкогнито не учитывать; доступ к нему не включать автоматически.

Если расширение отсутствует, потеряло связь или не имеет разрешения, продолжать учёт приложения браузера с пометкой «Без детализации по сайтам». Не угадывать домен по устаревшему событию. Сверять события браузера с фокусом Windows и их свежестью. При противоречиях выбирать честную неполную детализацию.

На экране состояния показывать: учёт работает/приостановлен, подключено ли расширение, время последнего события, состояние очереди Telegram и понятную причину ошибки. Пропуск данных сам по себе не трактовать как намеренный обход контроля.

**7. Интерфейс и первый запуск**

Предложение по интерфейсу — спокойное оформление, крупные числа, понятные подписи и минимум технических терминов. Предусмотреть масштабирование Windows и клавиатурную навигацию.

Основные экраны:

- «Сегодня»: учтённое время, дневной лимит, остаток или превышение, распределение по категориям, самые используемые программы и сайты, периоды активности и отметки неполных данных.
- «История»: день, неделя, месяц, выбор дат, детализация по приложениям и сайтам.
- «Категории»: ручные исправления правил.
- «Настройки»: имя профиля, часовой пояс, порог простоя, расписание отчётов, дневной лимит и предупреждения, срок хранения, Telegram, автозапуск.
- «Состояние и помощь»: диагностика, тестовый отчёт, версия, инструкция и ссылка на GitHub.
- «Поддержать разработку»: переход на страницу донатов.

Мастер настройки последовательно объясняет, какие данные собираются, указывает текущую учётную запись Windows, позволяет задать имя профиля, подключить расширение, создать собственного Telegram-бота по инструкции, локально ввести токен и проверить доставку. Установка расширения должна быть явным действием пользователя.

Для публичного Chrome обычный путь установки расширения — Chrome Web Store; установщик EXE не должен обещать незаметно установить произвольное расширение с GitHub. Для разработки допустима ручная загрузка распакованной версии. Публичная поставка браузерного компонента требует отдельной подготовки [12]. Для Edge использовать поддерживаемый им путь распространения и проверить его перед выпуском.

Не позиционировать PIN в интерфейсе как неуязвимую защиту: он может ограничивать обычное изменение настроек, но не действия программы в той же учётной записи или администратора ПК. Усиленная защита и жёсткие ограничения — отдельная будущая задача. Учёт должен быть видимым, с понятным состоянием и способом удаления.

**8. Telegram, запросы родителя и завершение сеансов**

В первой версии приложение самостоятельно отправляет сообщения и получает запросы через Telegram Bot API. Собственный сервер разработчика не требуется. Родитель создаёт своего бота и первым начинает с ним чат; бот не может сам начать личную переписку [13]. Во время первоначальной привязки сопоставить конкретный личный чат и числовой идентификатор Telegram-пользователя родителя через локальный код/подтверждение, а не выбирать первый найденный чат. После привязки не менять получателя автоматически.

Токен хранится только локально с защитой Windows DPAPI CurrentUser, не попадает в исходники, расширение, скриншоты мастера, журналы или экспорт. Эта защита привязана к учётной записи и не защищает секрет от произвольной программы, уже работающей с теми же правами [14].

Планируемые виды отчётов:

- После сеанса: например, после 15 минут простоя или блокировки, если приложение продолжает работать. Порог окончания сеанса отличается от 5-минутного порога простоя. В отчёт включается только учтённая активность; ожидание завершения сеанса не добавляется к ней.
- Вечерний снимок: по выбору пользователя, например в 21:00, с точной подписью «сегодня по состоянию на 21:00».
- Полный дневной итог: за завершившийся календарный день; формируется после его окончания и отправляется при ближайшей возможности.
- Недельный итог: за завершившуюся неделю в выбранном часовом поясе.
- По запросу родителя: кнопка «Отчёт за сегодня» или команда /today в Telegram; кнопка «Сколько осталось» или команда /remaining для краткой сводки лимита.
- Ручной отчёт: кнопка отправки из приложения.

Предлагаемые начальные настройки — отчёт после сеанса и полный дневной итог; вечерний снимок и недельный отчёт можно включить отдельно. Не выдавать вечерний снимок за полный день и не терять позднюю активность после него.

Если компьютер уснул или выключился до отправки, сообщение будет доставлено после следующего запуска/пробуждения и восстановления связи. Невозможно гарантировать немедленное уведомление с выключенного ПК без отдельного работающего сервера. При завершении Windows допустима попытка отправки, но надёжность должна обеспечиваться локальной очередью.

Сначала сохранять задание отчёта и его содержание в SQLite, затем отправлять. Идентификатор задания включает профиль, тип, период и версию сводки. После подтверждённого успеха сохранять идентификатор Telegram-сообщения. Предусмотреть повторные попытки с задержками для временных ошибок, соблюдение Retry-After, отдельное состояние неверного токена/недоступного чата и отсутствие бесконечного потока одинаковых ошибок.

Обычный перезапуск не должен заново отправлять уже подтверждённые задания. При сетевом тайм-ауте после возможной доставки результат может быть неопределённым: не обещать абсолютную гарантию «ровно один раз». Отчёт должен иметь короткий устойчивый идентификатор и период, чтобы возможный дубль был понятен. После длительного отсутствия связи сгруппировать накопившиеся итоги, сохранив покрытые периоды и не засыпая родителя десятками сообщений.

Отчёт содержит профиль, период и часовой пояс, основное время, дневной лимит при его включении, остаток или превышение, разбивку по категориям и приложениям/сайтам, самый длинный период без длительного перерыва, отдельное фоновое воспроизведение и существенные пропуски детализации. Все суммы должны сверяться с локальным экраном.

Для запросов получать обновления методом getUpdates с long polling; собственного входящего HTTP-сервера не требуется [13]. На один токен работает один получатель обновлений. Не запускать независимые опросы с одним токеном на разных компьютерах. Если для бота уже установлен webhook, показать конфликт настройки и не удалять чужую интеграцию молча.

Запрос разрешён только из привязанного личного чата и от числового Telegram user_id родителя. Проверять отправителя и у обычных сообщений, и у нажатий кнопок. Ник, имя и текст сообщения не являются проверкой личности. Обрабатывать только перечисленные команды. Расширение браузера не получает токен и не принимает команды управления.

Входящие запросы и их update_id сохранять до подтверждения получения, обеспечивать повторную обработку без повторного создания одного задания. Сетевое ожидание не должно останавливать сбор активности. Ограничивать частоту повторных запросов одного родителя; при серии одинаковых запросов допустимо объединение с одним актуальным ответом.

Отчёт /today строится из состояния движка на момент обработки, включая текущий ещё не закрытый интервал. /remaining использует те же расчёты. Не отвечать вчерашней сохранённой сводкой как текущей. Указывать дату, точное время среза, часовой пояс и время последнего наблюдения. Состояния «учёт приостановлен», «сеанс заблокирован» и неполные данные должны быть видны. Если лимит выключен, прямо написать это.

Пока компьютер включён, приложение работает и интернет доступен, цель — ответ в течение нескольких секунд, без обещания фиксированной задержки внешней сети. Если компьютер выключен, спит или приложение остановлено, немедленного ответа и даже немедленного сообщения «компьютер недоступен» от этой архитектуры не будет. Telegram хранит неполученные обновления не более 24 часов [13], поэтому не обещать бессрочное ожидание запроса. При обработке отложенного запроса явно подписать время формирования и текущую дату ответа; не выдавать его за снимок на момент нажатия кнопки. Для постоянно доступного ответа последней сохранённой статистикой понадобится отдельный сервер; в текущую версию он не входит.

**8а. Дневной лимит и уведомления**

Родитель задаёт лимит в настройках приложения: выключен или положительное число минут за день, например 120. В этой версии используется единый лимит на всё основное учтённое компьютерное время. Разные лимиты по категориям, дням недели и исключения для учебных программ можно добавить позднее. Возможность менять лимит из Telegram — отдельное предложение для будущего обсуждения; для текущих запросов /today и /remaining изменение настроек не требуется.

Лимит расходуется по тем же непересекающимся интервалам, что и основная статистика: учитываются все программы и сайты, включая поддерживаемое воспроизведение видео на переднем плане. Простой, сон, блокировка и пауза наблюдения не добавляются к расходу. Фоновое воспроизведение не расходует бюджет второй раз. Если есть пропуски наблюдения, остаток является оценкой по имеющимся данным — это нужно обозначить.

Расход суммируется за все сеансы одного календарного дня в настроенном часовом поясе. Например, 40 минут утром и 80 минут вечером достигают лимита 120 минут. Перезапуск приложения, браузера или ПК не обнуляет накопленный расход и уже сработавшие пороги. Новый календарный день начинается с новым счётчиком; история предыдущего дня сохраняется. Смена часового пояса не должна молча сбрасывать расход: выполнять явный пересчёт по выбранной политике, сохраняя историю изменения настройки.

Остаток равен максимуму из нуля и разности лимита и расхода. Превышение равно максимуму из нуля и разности расхода и лимита. Отображать эти значения раздельно, без отрицательного «оставшегося времени».

Базовое событие создаётся при достижении лимита, когда расход становится не меньше установленного значения. Родитель получает сообщение в Telegram, ребёнок — локальное уведомление. Текст при равенстве: «Дневной лимит 2 часа достигнут». При уже имеющемся превышении: «Лимит 2 часа превышен на 7 минут; учтено 2 часа 7 минут». Сообщение содержит профиль, дату, фактический расход, значение лимита и время события. Учёт после этого продолжается. Компьютер автоматически не блокируется, программы не закрываются.

Дополнительное предложение: одно предварительное уведомление ребёнку за 10 минут до исчерпания лимита; порог можно изменить или отключить. Пример: «На сегодня осталось 10 минут». Предупреждение родителю до достижения лимита включается отдельно. Если предупреждающий порог больше самого лимита, настройку нужно привести к допустимому значению и объяснить результат. При позднем запуске с уже превышенным лимитом не показывать сначала устаревшее «осталось 10 минут».

На один день и действующую редакцию лимита каждый порог создаёт не больше одного события. Статусы отправки вести отдельно по каналам Telegram и Windows; повторная проверка каждую секунду не должна создавать новые сообщения. По умолчанию постоянных повторов о превышении нет. После перезапуска не повторять подтверждённые события.

Если родитель увеличил лимит, пересчитать остаток без изменения фактического расхода; новое пересечение нового значения может создать новое событие. Если уменьшил лимит ниже уже использованного времени, сразу отразить превышение и создать одно уведомление с пояснением об изменении лимита. Повторное сохранение того же значения не считается новой редакцией. Историю настроек и порогов сохранять.

Локальный расчёт и уведомление на ПК работают без интернета. Telegram-уведомление сохраняется в надёжную очередь и отправляется после восстановления связи. Если к этому моменту начался следующий день или лимит изменился, текст сохраняет исходную дату, значение лимита и время события и пометку о задержке; нельзя выдавать вчерашнее превышение за сегодняшнее.

Для локальных уведомлений использовать штатный механизм Windows для .NET-приложений [18] и постоянный индикатор остатка/превышения в интерфейсе. В настройке нужен тест уведомления. Режим «Не беспокоить», отключённые уведомления и полноэкранная игра могут подавлять баннер [19]. Не гарантировать показ поверх любой игры и не отмечать событие как прочитанное ребёнком только по факту вызова API. При следующем открытии приложения сохранять видимую информацию о достигнутом лимите.

**9. Хранение и приватность**

Источником истины служат интервалы активности с началом, окончанием, приложением, доменом при наличии, состоянием и качеством наблюдения. Отдельно хранить дополнительные интервалы медиа, правила категорий, дневные агрегаты, версии схемы, настройки лимитов с редакциями, состояния сработавших порогов, разрешённые Telegram chat_id/user_id, входящие запросы, позицию получения обновлений и очередь отправки. Приложение является единственным владельцем записи в базу; расширение не пишет в неё напрямую.

Предлагаемый срок хранения: подробные интервалы 90 дней, дневные агрегаты 365 дней. Дать возможность менять срок и удалять историю вместе с её агрегатами и неотправленными отчётами. Объяснить, что удаление локальной истории само по себе не удаляет уже полученные сообщения Telegram.

Предусмотреть миграции базы при обновлении, ограничение размера диагностических журналов и сохранение данных при обычном обновлении. Для полной очистки при удалении приложения сделать отдельный явный выбор.

Не внедрять обязательную аналитику разработчика. Полная история остаётся на компьютере семьи; выбранные сводки передаются Telegram и хранятся в соответствующем чате. Не называть этот сценарий полностью офлайн или обещать сквозное шифрование переписки с ботом.

Сбор нажатий клавиш с содержимым, скриншотов, паролей, микрофона и камеры не требуется для указанной задачи и не входит в проект.

**10. GitHub, обновления и добровольные донаты**

Подготовить репозиторий с исходниками, инструкцией на русском, описанием измерений и ограничений, скриншотами, порядком сборки, журналом изменений и шаблоном сообщения об ошибке. Лицензию определить отдельно до публичного выпуска; нахождение проекта на GitHub само по себе не определяет лицензию.

Релиз содержит установщик Windows, пакет расширения для соответствующего канала поставки, заметки к версии и контрольные суммы. Подготовить воспроизводимый процесс сборки на Windows, например в GitHub Actions, и зафиксировать версии инструментов. Публикация и использование аккаунтов владельца выполняются только в рамках отдельно порученного выпуска; текущая задача ничего не публикует.

Для первой версии обновление — уведомление о новой стабильной версии со ссылкой на официальный GitHub Release. Автоматическое скачивание и замена исполняемых файлов требует отдельного безопасного механизма и не входит в минимальную версию. Цифровая подпись Windows и размещение расширения в магазине — отдельные работы выпуска; не заявлять их выполненными без фактического результата.

GitHub Releases подходит для готовых сборок [15]. Ссылка поддержки размещается в README и через FUNDING.yml; GitHub допускает внешние платёжные ссылки в кнопке Sponsor [16].

В приложении кнопка «Поддержать разработку» располагается в родительских настройках и разделе информации о проекте. В недельном отчёте допустима небольшая отключаемая ссылка. Донат добровольный, основные функции доступны независимо от него.

Использовать постоянную HTTPS-страницу поддержки под контролем владельца. Уже на ней размещать доступные способы оплаты, чтобы изменение платёжного сервиса не требовало новой версии приложения. Оплата проходит во внешнем браузере; приложение не принимает банковские данные и не передаёт вместе со ссылкой имена детей, историю или идентификаторы семьи. Сбор статистики нажатий не обязателен.

Конкретный платёжный сервис и адрес страницы пока не выбраны. Ничьи реквизиты не придумывать. Пока адрес не настроен, не показывать рабочую кнопку с фиктивной оплатой. Доступность получения средств проверить для страны проживания и банковского счёта владельца; GitHub Sponsors поддерживает не все регионы [17].

**11. Что оставить для следующих версий**

Кандидаты: несколько детей и устройств, дополнительные браузеры, названия YouTube-роликов по отдельному включению, экспорт отчётов, разные лимиты по дням недели и категориям, исключения для учебных программ, расписания и жёсткие ограничения, изменение лимитов и другие управляющие команды через Telegram, более сильная защита настроек, родительский кабинет и общий сервер для ответа при выключенном ПК. Запрос текущего отчёта и базовый дневной лимит с уведомлениями уже входят в первую версию. Каждое расширение оценивать по реальной пользе, расходам и дополнительным данным, которые оно потребует.

Наличие интерфейса для будущего расширения допустимо, но не строить заранее всю серверную инфраструктуру. Первая версия должна полноценно решать основной сценарий.

| Игра с фоновым видео и периоды сна | Бюджет не расходуется дважды; сон и блокировка не добавляют время |
| Достижение лимита | Одно событие на порог; отдельные уведомления родителю и ребёнку, затем продолжается учёт превышения |
| Лимит изменён в середине дня | Расход сохранён, остаток пересчитан; уменьшение ниже расхода создаёт одно объяснимое уведомление |
| Ночью начался новый день | Новый счётчик, сохранённые вчерашние данные; задержанные уведомления имеют исходную дату |
| Нет интернета при достижении лимита | Локальное уведомление возможно, сообщение Telegram остаётся в очереди |

| Донат | Открывается правильная HTTPS-страница без передачи данных ребёнка |

Автоматическими проверками покрыть прежде всего движок интервалов, суммирование, границы периодов, восстановление, авторизацию запросов, обработку повторных update_id, пороги дневного лимита и очередь доставки. Интеграцию с реальными играми, браузером, полноэкранным режимом, блокировкой, локальными уведомлениями и установщиком проверить на Windows. Сборка в CI не заменяет проверку активного рабочего стола.

Измерить нагрузку на CPU, память и диск во время игры и простоя и указать условия измерения. Не обещать «нулевую нагрузку». Если среды Windows нет, прямо перечислить непроверенные сценарии, не выдавая сборку за проверенный продукт.

**13. Порядок дальнейшей работы**

Сначала уточнить оставшиеся продуктовые решения этой версии: поддержку ОС и браузера, расписание сообщений, набор данных в отчёте, настройки предварительных предупреждений, необходимость PIN, стиль интерфейса и страницу поддержки. Сам факт наличия запросов отчёта и дневного лимита уже задан пользователем. По вопросам без ответа сохранять явно обозначенные предложения, не выдумывать сведения о компьютере и платёжных аккаунтах владельца.

После отдельного поручения начать разработку двигаться завершёнными этапами: учёт приложений и локальная история; детализация браузера и YouTube; Telegram с запросами и восстановлением доставки; дневные лимиты и уведомления обоим участникам; установщик, документация, донаты и подготовка выпуска. На каждом этапе сообщать, что реализовано, что проверено и какие ограничения остаются.

Начало разработки не является автоматическим поручением публиковать репозиторий, создавать платёжные аккаунты или отправлять сообщения реальным получателям. Эти действия выполнять в рамках конкретных последующих поручений пользователя.
