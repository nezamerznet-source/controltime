# Подготовка GitHub-релиза владельцем

Этот проект ещё не опубликован. Готовые исходники можно поместить в новый репозиторий после выбора названия, владельца и лицензии.

1. Выберите публичную лицензию, замените `LICENSE-NOT-SELECTED.md` и обновите ссылки на него в сборочном скрипте/README.
2. Укажите адрес репозитория и постоянной страницы поддержки в `branding.json`. Для GitHub-кнопки поддержки можно также заполнить `.github/FUNDING.yml`.
3. Пройдите `WINDOWS-ACCEPTANCE.md`, исправьте найденное, приложите реальные скриншоты и обновите `VALIDATION.md`.
4. Создайте репозиторий и загрузите исходники. Не включайте `artifacts`, `bin`, `obj`, файлы базы, токены и реквизиты подписи.
5. Workflow **Windows build** выполняет тесты и сохраняет комплект артефактов. Релиз, тег и страницу он не публикует.
6. Для публичного выпуска отдельно решите вопрос подписи приложения и магазинной версии расширения. Название издателя, лицензию, политику приватности и ID расширения нужно согласовать с аккаунтом владельца.
7. После проверки опубликуйте установщик, архив расширения, архив исходников, контрольные суммы и заметки к версии.

Сборочный workflow привязан к SHA официальных GitHub Actions. Зависимости сборки следует обновлять осознанно и повторять проверки после обновления. Выполненная локальная сборка не означает, что CI уже запускался в вашем репозитории.

Донат добровольный, функции от него не зависят. Страница поддержки открывается в браузере; имя профиля, история, Telegram ID и сведения об устройстве в ссылку не добавляются. Адрес не задан — кнопка скрыта.
