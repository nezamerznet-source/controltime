# Личный кабинет Family Time 0.2

Кабинет дополняет Windows-приложение версии 0.1.2. Telegram остаётся необязательным. Отправка отчёта перед выключением не добавляется.

## Для семьи

1. Откройте адрес кабинета, создайте аккаунт и подтвердите электронную почту. Ссылка подтверждения и восстановления пароля открывается в том же браузере, где отправлен запрос.
2. Установите FamilyTime-0.2.0-Setup.exe поверх 0.1.2: история и настройки сохраняются. При установленном родительском пароле штатное обновление потребует этот пароль.
3. В кабинете откройте «Компьютеры» → «Подключить компьютер» → «Получить код подключения».
4. В Windows: настройки → «Личный кабинет». Вставьте адрес кабинета и десятисимвольный код, нажмите «Подключить». Адрес должен начинаться с HTTPS. Пароль аккаунта в приложение не вводится.
5. Первые данные появятся обычно в течение минуты. Сохранившаяся локальная история также загружается; большой архив может загружаться несколько минут.

Можно смотреть кабинет на телефоне. Когда компьютер выключен, видна последняя переданная история. «Нет связи» означает отсутствие свежего подтверждения связи, а не достоверное выключение. Рядом указаны последняя синхронизация и время последнего наблюдения. Данные, которые компьютер ещё не успел отправить, появятся после его включения и восстановления интернета.

Пароль кабинета и локальный родительский пароль различаются. Кабинет показывает статистику и последний полученный лимит; дистанционное изменение лимита и блокировка компьютера в 0.2 не реализованы.

## Публикация: сначала GitHub, затем Vercel

Исходники Windows и кабинета находятся в одном репозитории. CI проверяет Core, расширение, установщик и WPF, затем веб-сборку, PostgreSQL/RLS и браузерные сценарии. Релиз установщика разрешён только после успешных проверок обеих частей. Повторный запуск не заменяет ранее опубликованные файлы версии.

### Supabase

Создайте отдельный проект в европейском регионе. Сохраните пароль базы в своём менеджере паролей. В SQL Editor однократно выполните `web/supabase/migrations/001_familytime.sql`. Миграция создаёт таблицы, изоляцию семей через Row Level Security и серверные функции привязки/синхронизации.

В Authentication включите Email с подтверждением адреса, укажите основной адрес кабинета как Site URL и добавьте `https://ВАШ-ДОМЕН/auth/callback` в разрешённые Redirect URLs. Для восстановления пароля разрешите также `https://ВАШ-ДОМЕН/auth/callback?next=password`. Для публичной регистрации настройте собственный SMTP: тестовая почтовая служба Supabase имеет ограничения получателей и отправки.

### Vercel

Импортируйте репозиторий GitHub. Root Directory: `web`. Framework: Next.js. Node.js: 24.x. Команда сборки: `npm run build`. Vercel должен получить исходники из GitHub после прохождения проверок.

Укажите переменные окружения Production (Preview должен использовать отдельную тестовую базу):

| Переменная | Значение |
| --- | --- |
| `SITE_URL` | Основной HTTPS-адрес кабинета без завершающего `/` |
| `SUPABASE_URL` | Project URL из Supabase |
| `SUPABASE_ANON_KEY` | Публичный anon/publishable ключ проекта |
| `SUPABASE_SERVICE_ROLE_KEY` | Серверный service_role/secret ключ проекта |

Все четыре переменные используются только сервером. Не добавляйте префикс `NEXT_PUBLIC_`, не размещайте ключи в GitHub, Windows-приложении или файлах для скачивания. Перезапустите deployment после настройки переменных. Без них сайт показывает экран подготовки и не имитирует работающий вход.

Приложение и браузер обращаются только к адресу кабинета; сервер Vercel соединяется с Supabase. Фактическая доступность без VPN зависит от провайдера и домена и должна проверяться с устройства семьи. Telegram не участвует в этой связи.

### Проверка после развёртывания

Зарегистрируйте два аккаунта с доступной почтой. Подключите тестовый компьютер к первому, убедитесь, что второй не видит ни его, ни историю. Проверьте доставку подтверждения и восстановления пароля, повторную отправку одного дня, отсутствие сети, последующее восстановление и удаление компьютера. Перед использованием с личной историей проверьте HTTPS и основной домен. Не публикуйте скриншоты реальных семейных данных в CI.

## Какие данные сохраняются

Передаются имя профиля, имя компьютера, часовой пояс, текущий лимит, состояния паузы и расширения, дневные итоги, названия программ, домены сайтов, категории и интервалы сеансов. Не передаются токены Telegram, локальный родительский пароль, снимки экрана, содержимое страниц, переписка и заголовки окон.

Секрет компьютера шифруется Windows DPAPI для текущего пользователя. На сервере хранится только SHA-256 этого случайного 256-битного секрета. Одноразовый код имеет 50 бит случайности, действует 10 минут, хранится как хеш и может привязать только один компьютер. Повтор точно того же подтверждённого запроса безопасен. Сервер ограничивает частоту запросов; RLS изолирует семейные данные даже при прямых запросах к Supabase от пользовательской сессии.

SQLite сохраняет очередь изменённых дней в одной транзакции с учётом. Каждая версия дня заменяет предыдущую целиком. Старые и повторные пакеты не добавляют минуты повторно. Подтверждение удаляет из очереди только отправленную версию; новые наблюдения остаются в очереди. Сначала обновляется сегодняшний день, затем архив; сегодняшний день отправляется не чаще раза в минуту. При ошибках интервал повторов растёт от 15 секунд до 5 минут. Отправка не привязана к выключению Windows.

Локальная подробная история и дневные итоги хранятся по настройкам приложения. В облаке дневные снимки и уже загруженные сеансы сохраняются до срока дневных итогов; очистка выполняется при следующей синхронизации. Если устройство больше не подключается, данные остаются до его удаления из кабинета. Локальная очистка истории не удаляет ранее загруженные дни; текущий день обнуляется после синхронизации. Удаление компьютера в кабинете немедленно удаляет облачные снимки и секрет и прекращает его доступ. Локальные данные при этом сохраняются.

## Разработка и протокол

В `web`: `npm ci`, `npm test`, `npm run build`, `npx playwright install chromium`, `npm run test:e2e`. Для разработки скопируйте `.env.example` в `.env.local` и заполните тестовый проект. Не используйте семейные данные для тестов. Браузерные тесты подменяют API только внутри Playwright; приложение не содержит демонстрационных аккаунтов или обхода авторизации.

`POST /api/device/claim`: `{code, deviceId, token, name}`. UUID и случайный токен создаются и сохраняются приложением до запроса. `POST /api/device/sync`: заголовок `Authorization: Bearer <token>`, JSON `{protocol:1, metadata, days:[...]}`. Ответ `{accepted:[{day,revision}]}`. Приложение отправляет по одному дню. HTTP 401 отзывает привязку; сетевые ошибки сохраняют очередь. Перенаправления HTTP запрещены. Формат валидируется в `web/lib/schema.ts`; соответствующие C# записи находятся в `src/FamilyTime.Core/Cloud.cs`.

База ограничивает доступ к функциям привязки и записи ролью `service_role`. Пользовательские сессии читают только свои устройства и снимки. Все изменения через браузер проверяют Origin, учётные данные проходят Supabase Auth, cookie HttpOnly/SameSite=Lax/Secure для HTTPS. Клиентский код не получает секретный ключ сервера.
